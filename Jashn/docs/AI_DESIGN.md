# AI System Design — Jashn Celebration & Event Planner

## 1. Core AI Philosophy

In **Jashn**, AI is designed as a **conversational strategist and parameter extractor**, **never as an unconstrained calculator**. 

Event planning involves hard financial commitments: vendor advance payments, venue hall contracts, and per-plate catering costs. A probabilistic model that hallucinated ₹50,000 extra or dropped ₹10,000 due to rounding would destroy user trust.

Therefore, Jashn implements a **Strict Delegation Pattern**:
1. **The AI interprets intent:** It parses natural language (e.g. *"Reduce total spend by 10% but ensure the photographer and venue remain unchanged"*).
2. **The AI outputs structured parameters:** It specifies `{ type: "cut_percentage", cutPercentage: 10, lockedCategories: ["photography", "venue"] }`.
3. **The Domain executes exact math:** Pure domain algorithms recalculate integer allocations in INR with exact summation:
   $$\sum \text{allocatedAmount} \equiv \text{targetBudget}$$

## 2. Gemini API Client & Ordered Model Failover

Jashn connects to Google Gemini via the official `@google/genai` SDK with an automatic priority failover chain managed by `ModelFailoverManager`:

```
1. gemini-2.5-flash  ───(If 429/503/Timeout)───► 60s Cooldown
       │
       ▼
2. gemini-1.5-flash  ───(If 429/503/Timeout)───► 60s Cooldown
       │
       ▼
3. gemini-1.5-pro    ───(If all fail)──────────► Deterministic Fallback
```

### Cooldown Policy
When any model call fails (e.g., rate-limit 429, service unavailable 503, or invalid format), the manager registers a timestamp:
```typescript
cooldowns.set(modelName, Date.now() + 60_000);
```
Subsequent requests skip cooling models, preventing cascade bottlenecks and conserving client quota.

## 3. Prompt Delimiting & Guardrails

To prevent indirect or direct prompt injection attacks, all queries are wrapped in rigid boundaries:
```
--- USER CELEBRATION PLANNING QUERY BEGIN ---
Cut 10% from the total but keep the photographer.
--- USER CELEBRATION PLANNING QUERY END ---
```

System instructions mandate strict JSON output:
```json
{
  "reply": "Friendly explanation of proposed changes...",
  "intent": "budget_cut",
  "proposedBudgetChange": {
    "type": "cut_percentage",
    "cutPercentage": 10,
    "lockedCategories": ["photography"]
  }
}
```

The response is validated via Zod (`AssistantStructuredOutputSchema`). If validation fails, the system automatically falls back to the deterministic engine.

---

## 4. Deterministic Offline Fallback Engine (`src/ai/fallback.ts`)

Jashn works **100% offline and without requiring an API key**. 

When `GEMINI_API_KEY` is not present, or during network disruptions, queries pass to the built-in deterministic engine:
- **Budget Adjustments:** Regex parsers detect cut percentages and mentioned categories (venue, caterer, photographer), invoking `simulateBudgetCut(plan.items, percent, locked)`.
- **Vendor Queries:** Returns current vendor allocations and recommended booking windows.
- **Menu & Decor Guidance:** Extracts relevant catering rules and curated ideas from `CURATED_IDEAS`.

---

## 5. Transparent Source Attribution

Every answer rendered in the UI prominently displays its origin:
- `Source: Gemini (gemini-2.5-flash)` — when generated by Google Gemini.
- `Source: Deterministic planner` — when generated by the offline rule engine.

This transparency provides users with full visibility into how their plan suggestions were generated.
